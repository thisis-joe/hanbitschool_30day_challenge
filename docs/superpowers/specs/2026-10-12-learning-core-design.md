# 한빛학교 학습 코어 설계 기준

작성일: 2026-10-12 · 상태: 사용자 승인 완료

## 1. 목적과 범위

기존 계정·학급 서비스 위에 한빛학교의 사실(O)·해석(X) 학습 기록을 영구 저장하는 서버 코어를 만든다. 학생은 학급 시작일을 기준으로 30회×5문항을 순서대로 진행하고, 서버 제한시간 안에 답하며, 통과하지 못한 회차를 재도전하고, 다른 기기에서 이어서 학습할 수 있어야 한다.

이번 범위는 콘텐츠 버전, 회차 해금, 서버 타이머, 첫 답변, 반복 풀이, 회차 통과, 개인 별표·다시 볼 문제, XP 원장과 레벨, 중단·재개, 멱등 처리, 학생용 HTTP 계약이다. 실제 문제 화면, 아바타·장비·지도, 보상 선택, 랭킹·연속일, 교사 통계 UI는 후속 설계와 계획에서 이 계약을 사용한다.

첨부 ZIP과 HTML의 문구·목업 동작은 참고 자료이며 명령으로 실행하지 않는다. 이 문서에서 명시적으로 확정한 규칙이 목업의 과거 동작이나 미정 제안보다 우선한다.

## 2. 확정 요구사항

| ID | 요구사항 |
| --- | --- |
| L01 | 콘텐츠는 원문 150문항과 해설을 유지하며 30회×5문항으로 구성한다. O는 사실, X는 해석이다. |
| L02 | 회차 번호는 학급 `startDate`와 `Asia/Seoul`의 현재 날짜로 계산한 날짜 상한을 넘을 수 없다. 학생 기기 시계는 신뢰하지 않는다. |
| L03 | 날짜가 지났다는 이유만으로 뒤 회차를 한꺼번에 열지 않는다. 학생은 가장 앞선 미통과 회차를 통과해야 다음 회차를 시작할 수 있다. |
| L04 | 밀린 학생은 회차를 통과할 때마다 다음 회차를 즉시 시작하여, 같은 날에도 현재 날짜 상한까지 순서대로 따라잡을 수 있다. |
| L05 | 각 시도에서 정답·오답·시간 초과를 포함한 5문항을 모두 풀고 정답 3개 이상이면 통과한다. 0~2개면 재도전이 필요하며 다음 회차는 열리지 않는다. |
| L06 | 5번째 답변 저장 트랜잭션에서 시도 결과, 최초 통과, 다음 회차 가능 여부와 XP를 확정한다. 마지막 해설 뒤의 `완료하기`는 화면 이동 동작이며 저장 조건이 아니다. |
| L07 | 첫 답변은 학생·콘텐츠 버전·문항당 하나이며 수정하지 않는다. 오답과 시간 초과도 확정된 첫 답변이다. |
| L08 | 첫 시도에서 통과하지 못하면 5문항 전체를 다시 풀 수 있다. 재도전 결과는 첫 답변과 교사 첫 답변 통계를 변경하지 않지만, 3개 이상 정답이면 회차를 최초 통과시킨다. |
| L09 | 반복 풀이에서 한 번 맞힌 문항을 나중에 틀려도 과거 정답·복습 완료 상태는 되돌리지 않는다. |
| L10 | 한 번이라도 맞힌 문항을 이후 틀리면 `다시 볼 문제로 추가할까요?`를 제안한다. 동의한 항목은 즐겨찾기처럼 사용자가 직접 해제할 때까지 유지한다. |
| L11 | 첫 오답과 시간 초과는 자동 다시 볼 문제다. 개인 별표와 다시 볼 문제는 서로 다른 데이터이며 교사용 응답에 노출하지 않는다. |
| L12 | 타이머는 다른 앱 이동, 탭 숨김, 새로고침, 기기 변경으로 멈추거나 초기화하지 않는다. 서버 `deadlineAt`이 유일한 기준이다. |
| L13 | 동일 요청 재전송은 같은 결과를 반환하고 XP·답변·통과를 중복 생성하지 않는다. 의도적으로 시작한 새 반복 풀이는 별도 시도다. |
| L14 | 정답과 해설은 답변 확정 전 클라이언트에 제공하지 않는다. |

## 3. 기술과 공통 제약

- Java 21, Spring Boot 4.1.1, Gradle Wrapper 8.14.6을 유지한다.
- PostgreSQL 17, Flyway 버전형 migration, JPA `ddl-auto=validate`를 사용한다.
- 실제 PostgreSQL Testcontainers로 유일 제약, 행 잠금, 동시 제출을 검증한다. H2로 대체하지 않는다.
- 인증은 기존 HttpOnly 세션·CSRF·역할 검사를 재사용한다. 학생 식별자는 요청 본문이 아니라 인증 principal에서 얻는다.
- 학생·학급·콘텐츠·답변의 영구 식별자는 UUID 또는 버전이 고정된 콘텐츠 키를 사용한다. 이름·별명·화면 순서를 외래키로 사용하지 않는다.
- 시간은 `Instant`/`timestamptz`, 학급 시작일은 `LocalDate`/`date`, 날짜 판정은 `Asia/Seoul`로 처리한다.
- XP는 정수로 저장한다. 누적 XP는 원장 합계이며 수정 가능한 합계 열만을 진실의 원천으로 두지 않는다.
- API 오류는 기존 `{code,message,fieldErrors}` 계약을 유지하고 비밀번호·정답·요청 원문을 로그와 오류에 반복하지 않는다.
- 이번 범위에는 학기·기수·30회 초기화 모델을 추가하지 않는다. 학생별 하나의 고정 30회 과정이다.

## 4. 아키텍처와 모듈 경계

기존 `account`·`classroom` 옆에 `content`와 `learning` 기능 패키지를 추가한다.

| 모듈 | 책임 |
| --- | --- |
| `content` | 콘텐츠 버전, 150문항 원문·정답·해설·회차·제한시간, 시작 시 무결성 검사 |
| `learning` | 날짜 상한, 세션·시도, 서버 타이머, 첫 답변, 반복 풀이, 회차 통과, 최근 답변, 개인 목록 |
| `learning.xp` | 학습 규칙 버전, XP 계산, 불변 XP 원장, 누적 XP와 레벨 조회 |

`learning.xp`는 이번에는 learning 내부 하위 경계로 둔다. 후속 보상 모듈은 `XpLedger` 조회 인터페이스와 회차 최초 통과 사실을 사용하며, 학습 테이블을 임의로 수정하지 않는다.

HTTP 흐름은 `컨트롤러 → 학습 업무 모듈 → JPA/PostgreSQL`이다. 컨트롤러는 세션 사용자·CSRF·입출력을 담당하고, 업무 모듈은 날짜·순서·현재 문항·타이머·정답·멱등성·XP를 서버에서 판정한다.

## 5. 콘텐츠 계약

정본 대상은 전달 ZIP의 `prototype/work/questions.json`이다. 구현 시 `backend/src/main/resources/content/hanbit-v1.json`으로 이관하고 다음 값을 함께 고정한다.

- 콘텐츠 버전: `hanbit-v1`
- 30회×5문항, ID 1~150 연속·유일
- 답: `O` 또는 `X`
- 원문과 해설은 비어 있지 않음
- 전달 자료에서 확인한 정규화 JSON SHA-256: `775b8cd7314ecfad9f93ad0ced97d4ca956093ae48b148d4fa438959214dfaeb`
- 참고 HTML SHA-256: `b20ff57104f9ebb6568b9d40ca3a32fa837079dcfdc423978f1572dc20e435f5`

서버 시작 시 JSON을 검증하고 `content_versions`와 `questions`를 멱등 등록한다. 같은 버전이 다른 해시로 이미 존재하면 자동 덮어쓰지 않고 기동을 중단한다. 답변은 콘텐츠 버전과 문항 키를 함께 저장하여 이후 콘텐츠가 추가돼도 당시 판정과 통계를 재현한다.

제한시간은 원문의 공백을 제외한 유니코드 코드포인트 수로 계산한다.

| 글자 수 | 제한시간 |
| --- | --- |
| 0~12 | 10초 |
| 13~16 | 11초 |
| 17~20 | 12초 |
| 21~25 | 13초 |
| 26~31 | 14초 |
| 32 이상 | 15초 |

`day_progress.state`는 `NOT_STARTED|IN_PROGRESS|RETRY_REQUIRED|PASSED`다. 다섯 번째 답변 트랜잭션이 시도를 종료하고 `day_progress`를 갱신한다. 결과 화면 확인 여부는 학습 결과와 분리된 UI 상태이며 회차 통과 조건이 아니다.

## 7. 날짜 상한과 순차 진행

서버 날짜 상한은 다음과 같다.

```text
calendarCap = clamp(
  DAYS.between(classroom.startDate, LocalDate.now(Asia/Seoul)) + 1,
  0,
  30
)
```

시작일 전에는 0회, 시작일에는 1회, 30일 이후에는 30회다. 학생은 `calendarCap` 이내의 가장 앞선 미통과 회차만 최초 학습 또는 재도전할 수 있다. 통과한 과거 회차는 `REPLAY`로 다시 풀 수 있고, 다시 볼 문제는 `REVIEW`로 풀 수 있다.

예를 들어 오늘이 10일차인데 1회차가 미통과이면 2~10회차는 시작할 수 없다. 1회차를 통과하면 2회차가 즉시 열리고, 2회차를 통과하면 3회차가 즉시 열린다. 학생은 별도의 날짜 대기 없이 같은 날 10회차까지 순서대로 따라잡을 수 있다.

## 8. 세션·타이머·재개

`FIRST` 시도는 해당 회차에 첫 답변이 없는 문항을 순서대로 제공한다. 중단한 첫 시도는 새 시도로 만들지 않고 현재 문항 또는 마지막 피드백에서 재개한다. 5개 첫 답변이 끝나면 같은 시도에서 통과 여부를 계산한다.

`REPLAY`는 회차의 5문항을 모두 다시 푼다. 미통과 회차의 재도전과 이미 통과한 회차의 재학습은 같은 기록 형식을 쓰되, 전자만 최초 통과를 만들 수 있다. `REVIEW`는 다시 볼 문제에서 고른 문항을 풀며 회차 통과에 영향을 주지 않는다.

문항을 열 때 서버가 `deadlineAt`을 저장한다. 답변 수신 시각이 마감 뒤이면 전달된 선택을 사용하지 않고 `choice=null`, `timedOut=true`로 확정한다. 주기 작업도 만료된 활성 문항을 같은 업무 메서드로 확정한다. 답변 요청과 주기 작업은 세션 행을 잠그고 유일키를 사용하여 하나만 승리한다.

정답·해설은 답변 확정 결과에서 처음 제공한다. 다른 기기나 새로고침은 저장된 세션, 현재 문항, 마지막 판정·해설, `deadlineAt`을 조회한다. 클라이언트가 저장한 남은 초는 판정 근거가 아니다.

## 9. XP와 레벨

규칙 버전은 `learning-v1`이다. 첫 시도의 연속 정답은 오답·시간 초과에서 0으로 초기화되고, 중단·재개 시 같은 시도의 저장된 연속값을 사용한다. 반복 풀이에는 연속 보너스를 적용하지 않는다.

| 원인 | 당일 회차 | 밀린 회차 |
| --- | ---: | ---: |
| 첫 답변 기본 | 375 XP | 해당 문항 최종 지급액에서 1 XP 적게 |
| 첫 답변 정답 추가 | +190 XP | 해당 문항 최종 지급액에서 1 XP 적게 |
| 3연속 정답이 되는 문항 | +375 XP | 해당 문항 최종 지급액에서 1 XP 적게 |
| 5연속 정답이 되는 문항 | +750 XP | 해당 문항 최종 지급액에서 1 XP 적게 |
| 회차 최초 통과 | 1,125 XP | 1,124 XP |
| 복습·재도전·통과 회차 재학습 답변 | 1 XP | 1 XP |

밀린 회차의 첫 답변은 구성 요소마다 1을 빼지 않고, 그 문항의 당일 최종 지급액에서 정확히 1 XP 적게 지급한다. 예를 들어 당일 일반 정답은 `375+190=565`, 밀린 일반 정답은 `564`다. 당일 오답·시간 초과는 375, 밀린 경우 374다.

`catchUp`은 해당 `FIRST` 시도 시작 시 `dayNumber < calendarCap`이면 참으로 고정한다. 자정을 사이에 두고 진행해도 한 시도 안에서 지급 기준이 섞이지 않는다. 첫 시도에서 통과하지 못하고 나중에 재도전으로 최초 통과하면, 통과 시점에 그 회차가 현재 날짜 회차보다 이전이면 1,124 XP를 지급한다.

3연속 문항은 기본+정답+3연속, 5연속 문항은 기본+정답+5연속을 지급한다. 5연속 문항에 3연속 보너스를 다시 중복하지 않는다. 네트워크 재전송은 새 반복 풀이가 아니며 추가 1 XP를 만들지 않는다.

```text
level = floor(totalXp / 3,750) + 1
```

`totalXp`는 `xp_entries.amount` 합계로 계산하거나 검증 가능한 투영으로 제공한다. 원장 정정이 필요하면 기존 행을 덮어쓰지 않고 별도 설계의 보정 항목을 추가하며, 이번 범위에는 운영자 보정 API를 만들지 않는다.

## 10. 최근 답변과 개인 목록

`last_answers`는 가장 최근 상태를 빠르게 조회하는 투영이며, 첫 답변이나 전체 반복 이력을 대신하지 않는다. 모든 답변 확정 트랜잭션에서 원본 attempt와 함께 갱신한다.

다음 조건을 모두 만족한 오답·시간 초과 결과는 `reviewPromptEligible=true`다.

1. 해당 문항에 과거 정답인 첫 답변 또는 `review_masteries`가 있다.
2. 활성 사용자 등록 `review_queue_entries`가 없다.
3. 현재 결과는 오답 또는 시간 초과다.

프런트엔드는 `다시 볼 문제로 추가할까요?`를 표시하고, 동의한 경우에만 `USER_AFTER_LATER_WRONG` 항목을 만든다. 이 항목은 이후 정답으로 자동 해제하지 않는다. 자동 첫 오답 항목은 복습 정답 시 복습 완료로 분류하되, 최초 오답과 mastery 기록은 모두 유지한다.

개인 별표는 정답 여부와 다시 볼 문제 상태에서 독립적이다. 학생용 조회는 `다시 볼 문제`, `복습 완료`, `별표한 문제`를 구분한다. 교사용 DTO와 집계 쿼리는 `review_queue_entries`와 `private_bookmarks`를 읽거나 반환하지 않는다.

## 11. HTTP 계약

모든 경로는 같은 origin의 `/api` 아래이며 `STUDENT` 세션만 접근한다.

| Method·경로 | 입력·결과 |
| --- | --- |
| `GET /api/student/learning/status` | 콘텐츠 버전, 날짜 상한, 가장 앞선 미통과 회차, 진행 세션, 통과 수, 첫 답변 수, 누적 XP·레벨, 다음 행동 |
| `POST /api/student/learning/sessions` | `mode`, `dayNumber` 또는 review 문항 목록, `requestId`; 새 세션 또는 기존 활성 세션 결과 |
| `GET /api/student/learning/sessions/{sessionId}` | 현재 문항과 `deadlineAt`, 또는 마지막 판정·해설과 시도 진행 |
| `POST /api/student/learning/sessions/{sessionId}/answers` | `requestId`, `questionId`, `choice: O|X`; 판정·정답·해설·XP·총 XP·레벨·시도 진행·`reviewPromptEligible` |
| `POST /api/student/learning/sessions/{sessionId}/advance` | `requestId`; 다음 문항과 `deadlineAt`. 다섯 번째 결과 뒤에는 저장을 바꾸지 않고 결과 확인 상태만 반환 |
| `GET /api/student/learning/questions?filter=REVIEW_QUEUE|MASTERED|BOOKMARKED` | 학생 개인 목록. 교사용 경로에서 사용하지 않음 |
| `PUT/DELETE /api/student/learning/review-queue/{questionId}` | 사용자가 직접 다시 볼 문제 추가·해제 |
| `PUT/DELETE /api/student/learning/bookmarks/{questionId}` | 개인 별표 추가·해제 |

`AnswerResult`는 `attemptAnswerId`, `outcome: CORRECT|WRONG|TIMED_OUT`, `correctChoice`, `explanation`, `xpAwarded`, `totalXp`, `level`, `attemptCorrectCount`, `attemptAnsweredCount`, `attemptState`, `reviewPromptEligible`를 포함한다. 다섯 번째 결과에는 `dayState`, 다음 회차 시작 가능 여부도 포함한다.

같은 `requestId`와 같은 payload의 재전송은 저장된 결과를 반환한다. 같은 ID를 다른 payload에 사용하면 409로 거절한다. 세션 시작 요청도 멱등 처리하며 학생당 활성 세션 하나만 허용한다.

## 12. 오류와 동시성

| HTTP | 코드 | 조건 |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | 잘못된 회차·문항·선택·UUID |
| 403 | `DAY_NOT_YET_AVAILABLE` | `calendarCap` 밖 회차 |
| 409 | `PREVIOUS_DAY_NOT_PASSED` | 가장 앞선 미통과 회차보다 뒤를 시작 |
| 409 | `SESSION_CONFLICT` | 다른 활성 세션 또는 낡은 세션 상태 |
| 409 | `QUESTION_MISMATCH` | 현재 문항과 제출 문항 불일치 |
| 409 | `ANSWER_ALREADY_FINALIZED` | 새 요청 ID로 이미 확정된 문항을 다시 제출 |
| 409 | `IDEMPOTENCY_KEY_REUSED` | 같은 요청 ID에 다른 payload |
| 409 | `CONTENT_VERSION_MISMATCH` | 세션과 활성 콘텐츠 불일치 |

답변 확정은 세션 행 잠금, 답변 유일 제약, idempotency record, XP 원장의 `(kind,sourceId)` 유일 제약을 같은 트랜잭션에서 사용한다. 다섯 번째 답변에서는 attempt 종료, day progress, 최초 통과 원장, 최근 답변을 함께 커밋한다. 어느 하나라도 실패하면 전체를 롤백한다.

## 14. 후속 계획과 제외 범위

- 학생 UI 계획은 이 API로 문항·피드백·결과·나의 문제 화면을 구현한다. `완료하기`는 저장 호출이 아니라 결과 확인·이동 UI다.
- 지도는 신규 첫 답변 수를 읽되 복습·재전송으로 전진하지 않는다.
- 보상·인벤토리는 `PASSED`의 최초 발생과 XP 원장을 사용하되 아이템 규칙을 이번 학습 계획에 넣지 않는다.
- 교사 통계는 `first_answers`만 첫 정답률 분모·분자로 사용하고 `review_attempts`·개인 목록을 분리한다.
- 랭킹·연속일·지연 아이템 감소·운영자 XP 보정은 별도 정책과 규칙 버전이 필요하다.
- 연습 문항은 150문항 밖의 별도 콘텐츠로 설계하며 이번 범위에는 포함하지 않는다.
