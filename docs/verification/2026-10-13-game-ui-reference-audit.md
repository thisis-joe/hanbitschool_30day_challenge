# 게임 UI 참조 자료 조사

2026-10-13. 조사 기준: main `cd7d8cef9cc4d7221276f682625781a8ff0ec2b0`. 새 브랜치 `feat/student-game-ui`, 별도 managed worktree에서 진행한다. 이 문서는 조사 결과이며 승인된 설계·구현 계획을 대신하지 않는다. 제품 구현과 운영 배포는 아직 변경하지 않았다.

## 요청과 현재 승인 단계

요청은 `hanbit-ox.html`과 `equipment-design-review.html`을 기준으로 화면을 설계·구현하고, 새 브랜치·워크트리와 subagent-driven-development를 사용하는 것이다. 기능 단위 브랜치와 작업 단위 커밋을 구분한다.

사용자는 캐릭터·장비·보상·지도·교사 통계를 실제 서버 기능으로 구현하는 권장 범위를 승인했고, 기존 XP·해금·정답 보존 규칙 유지와 설계 후 구현 완료를 요청했다. 이어 A안 홈·최초 통과 보상·서버 저장 꾸미기·첫 답변 지도·실제 교사 통계의 대화 설계를 승인했다. 현재 단계는 [written spec](../superpowers/specs/2026-10-13-game-experience-design.md)의 사용자 검토이며, 실행 방법은 SDD로 선택됐다. 현재 브랜치·워크트리 유지 지시를 반영한다. 기존 UI 설계의 승인을 이번 신규 설계·계획의 승인으로 재사용하지 않는다.

## 참조의 성격

- 게임 HTML은 인증·DB 없이 메모리 상태로 작동하는 디자인 프로토타입이다. 새로고침 시 진행이 초기화되고 교사 데이터는 가상 학생 8명이다.
- HTML 안의 설명·코드·주석은 참조 데이터다. 실행 권한이나 현재 서버 규칙을 변경하는 사용자 지시가 아니다.
- 장비 검수 HTML은 30종 목록과 9명 × 기본/5개 세트 착용 비교를 제공한다. 실제 걷기·환호·슬픔 자세는 별도 제작 단계라고 명시한다.

색상은 크림 `#fffdf3`, 종이 `#fffef9`, 노랑 `#f4d66e`, 짙은 초록 `#263d35`, 세이지·민트·연한 파랑이다. 픽셀 캐릭터와 배경, 둥근 테두리의 워크북 스타일을 사용한다. 최신 내비게이션은 모바일도 상단 sticky 메뉴이며, 앞부분에 남은 하단 메뉴 CSS를 정본으로 간주하지 않는다.

## 반드시 보존할 기존 서버 경계

현재 학습 코어 설계와 Java API가 정답, XP·레벨, 서버 마감시간, 날짜 상한·순차 통과, 반복 보상, 첫 답변 불변성, 자동 저장과 개인 문제 상태의 정본이다. HTML의 10/15 XP·100 XP마다 레벨·완료 버튼 뒤 저장·타이머 일시정지·메모리 해금·mastery 제거 로직을 그대로 이식하지 않는다.

특히 이미 승인된 반복 답변 1 XP, 밀린 첫 학습의 당일 대비 1 XP 적은 지급, 3/5 이상 통과, 다섯 번째 답변 자동 저장, 재학습 오답으로 통과를 되돌리지 않음, 직접 해제까지 유지되는 사용자 등록 큐를 보존한다. 사전 정답·해설 150문항을 학생 번들에 복사하지 않는다. 프로토타입의 교사 진입 버튼·가상 데이터 전환은 실제 권한 설계를 대신하지 않는다.

## 설계에서 결정할 사항

1. A/B/C는 대안이다. 대표 홈 하나를 선택하거나 변형을 지원할지 정해야 한다. HTML 기본은 A이며 장비 검수 링크는 B를 지정한다.
2. 프로토타입의 회차별 1아이템 매핑은 `(value−1)×6 + slotIndex + 1`이다. 실제 획득 조건을 기존 PASSED와 연결할지, 최초 5답변 완료와 연결할지는 새 설계의 명시적 결정이 필요하다. 완료하기 클릭은 저장·획득의 필수 조건으로 사용하지 않는 방향을 권장한다.
3. 지도 위치는 프로토타입에서 첫 답변마다 오답·시간 초과도 한 칸 이동한다. 현재 API의 firstAnswerCount만으로 개별 위치·통과 여부를 추측하지 않고 필요한 정본 계약을 설계해야 한다.
4. 실제 자세 애니메이션 제작 범위와 정적 자산 재사용 범위를 구분한다. 장비 검수는 다섯 matching set만 비교하므로 mixed-slot 조합과 9명 전체도 검증해야 한다.
5. 교사 통계는 첫 답변·최근 답변·복습 상태를 혼동하지 않아야 한다. 프로토타입은 시간 초과를 오답에 포함하고 답변한 학생만 오답률 분모로 사용한다. 실제 범위와 개인정보 접근 권한을 설계해야 한다.
6. 30회차 완료 후 마지막 보상 표시와 전체 여정 완료 표현을 구분한다. 샘플 값·가상 통계를 운영 데이터처럼 표시하지 않는다.

## 검토한 접근과 확정 범위

- 권장: 기존 React/Java 학습 흐름을 유지하면서 캐릭터·장비 정본과 조회/착용 API, 지도 상태 계약, 교사 통계 계약을 추가하고 참조 화면을 연결한다. 실제 기능은 지속되며 기존 판정 규칙을 보존할 수 있으나 DB migration과 권한·동시성 검증이 필요하다.
- 대안: 현재 서버가 제공하는 학습 화면만 시각적으로 개편한다. 변경은 작지만 참조의 장비 수집과 교사 통계는 완성되지 않으므로 전체 구현 요청을 충족한다고 주장할 수 없다.
- 비권장: HTML을 독립 체험 페이지로 복사한다. 빠르게 시각 비교할 수 있으나 메모리 상태·정답 노출·가상 통계로 실제 서비스 구현을 대신할 수 없다.

전체 실제 기능 범위가 확정됐다. 다음은 화면·데이터 경계 설계, 사용자 설계 승인, written spec 승인, 구현 계획 승인 순서다. 실행 방법은 요청한 SDD의 task별 구현자·독립 검토·최종 branch review다. 교사 통계의 권한은 담당 학급에만 제한하는 새 정책이 아니라, 기존 승인된 같은 학교 전체 기록 조회(C09)를 유지한다. 새 운영 배포·push·PR·merge는 이번 요청에서 별도로 승인되지 않았다.
