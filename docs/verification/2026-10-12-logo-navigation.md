# 로고 클릭 후 로그인 화면 이동 수정 검증

- 날짜: 2026-10-12
- 변경 범위: 프런트엔드 루트 라우팅과 회귀 테스트. 백엔드 인증 및 가입 정책은 변경하지 않음.

## 원인과 변경

수정 전 로고는 `/`로 이동하고, 루트 라우트는 세션 상태와 무관하게 `/login`으로 이동했다. 실제 Chromium 재현에서 로고 클릭 전후 `/api/auth/me`는 모두 200이었으며 로그아웃 요청은 0건이었다. 세션은 유지되고 화면 이동만 잘못된 상태였다.

루트 라우트가 세션 확인을 기다린 뒤 기존 `accountPath`에 따라 학생은 `/student/account`, 교사·관리자는 `/staff/classrooms`, 초기 비밀번호 교체가 필요한 교직원은 `/account/password`로 이동하도록 수정했다. 미로그인은 `/login`, 세션 조회 실패는 오류와 재시도 화면을 표시한다.

## 검증

- RED: 수정 전 프런트엔드 전체 테스트 30개 중 신규 회귀 6개 실패, 24개 통과. 학생·교직원 로고 이동, 비밀번호 변경 유지, 세션 확인 대기, 네트워크 실패 처리가 잘못되는 것을 확인.
- 첫 GREEN 실행: 신규 회귀는 통과했지만 기존 `schoolChangeClearsGradeAndClass`가 학교 선택 항목 대기 시간 초과로 실패(29 통과, 1 실패). 이 실패를 제외하지 않고 전체 테스트를 다시 실행함.
- 최종 GREEN: `node node_modules/vitest/vitest.mjs run --maxWorkers=1 --no-file-parallelism`으로 8개 파일, 30개 테스트 모두 통과. 작업 부하를 줄여 파일을 순차 실행했으며 테스트 기대값과 대기 시간은 완화하지 않음.
- TypeScript/Vite 빌드 및 ESLint 통과.
- 실제 PostgreSQL을 사용하는 Chromium `role-switch.spec.ts`: 1개 통과. 로고 클릭, 루트 직접 접근, 새로고침 후 학생 화면·세션 유지, 계정 전환 후 교직원 화면 노출 차단을 확인.
- 별도 실제 로컬 학생 계정으로 로고 클릭·홈 접근·새로고침 모두 확인: 같은 계정, `/api/auth/me` 200, 로그아웃 요청 0건.
- 로컬 Docker 프런트엔드 재빌드·적용 완료. 백엔드와 DB는 정상 실행 상태를 확인했고 변경을 위해 재시작하지 않음.

백엔드 코드는 변경하지 않아 이번 수정에서는 백엔드 전체 테스트를 다시 실행하지 않았다. 전체 12개 브라우저 테스트도 다시 실행하지 않고 변경 경로를 포함하는 1개를 실행했다. 이전 계정·학급 전체 검증은 `2026-10-12-account-classroom.md`에 기록되어 있다.
