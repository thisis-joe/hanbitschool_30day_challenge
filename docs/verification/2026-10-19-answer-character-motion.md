- 최종 통합 기준: `22ec29c` (`origin/main`, 보상 PR #8 포함; 최초 구현 기준은 `76406ba`)
- main 통합 후 구현 커밋: `b9a9af2` (관절·포즈·표정 렌더링), `60f32da` (선택 이동·학습 연결·검수 화면).
- 다른 작업의 미커밋 변경을 보존하기 위해 별도 관리 워크트리에서 구현했다.

## 구현 범위

기존 9명의 원본 캐릭터와 장비 아트를 재사용한다. `motion/poses.ts`의 기본, 걷기 좌우, 양팔 들기, 점프, 풀이 죽기 6종 포즈를 `motion/rig.ts`가 몸통·팔·다리 레이어에 적용한다. 긴 머리와 모자는 몸통을 따라 움직이고 손 장비는 손의 회전을 따른다. 신규 래스터 그림이나 외부 이미지 서비스 의존성은 없다.

O/X 클릭으로 기존 답변 요청을 즉시 전송한다. 같은 요청에 기록된 선택을 읽어 750ms 동안 해당 위치로 이동한다. 서버의 결과가 빨리 와도 이동을 마친 뒤 반응한다. 늦으면 선택 위치에서 기다린다. 정답에는 웃는 표정과 양팔을 올린 두 번의 점프, 오답에는 허리를 약간 숙이고 팔을 내리는 자세를 보여 준다. 선택 없이 확정된 시간 초과는 가운데에서 풀이 죽은 자세를 보여 준다.

결과 복원 시 서버의 O/X 정답과 판정으로 선택 위치를 복구하고 정지된 결과 자세를 보여 준다. 같은 답변 재조회나 재시도는 동작을 다시 시작하지 않는다. 다음 문항에서는 가운데로 초기화한다. 애니메이션 이벤트가 답변·진행 API를 호출하지 않으며, 장비 로딩 실패 시 기존 정지 캐릭터로 대체한다. 첫 풀이·재도전·선택 복습에 같은 동작을 적용한다.

`prefers-reduced-motion`에서 좌우 이동 전환과 점프를 끄고 최종 감정 자세를 유지한다. 점프는 1.2초, 풀이 죽는 전환은 450ms 뒤 프레임 예약을 중지한다. 화면 이탈 시 예약과 로딩을 취소한다.

## 자동 검증 — 통과

- `pnpm --dir frontend test`: 최신 main 통합 및 보상 순서 수정 후 39개 파일, 304개 테스트 통과. 최초 구현 브랜치에서는 39개 파일, 302개가 통과했고, 보상 PR 통합 전 main 후보에서는 38개 파일, 299개가 통과했다.
- `pnpm --dir frontend build`: TypeScript 검사 및 Vite 배포 번들 생성 통과.
- `pnpm --dir frontend lint`: 통과.
- `git diff --check`: 통과.

추가 회귀 검증은 즉시 채점·느린 채점의 순서, 양쪽 도착, 결과 복원, 선택 취소, 다음 문항 타이머 정리, 두 번의 점프 종료, 동작 줄이기 포즈를 포함한다. 학습 페이지 통합 테스트는 FIRST/REPLAY/REVIEW 각각에서 이동 시작 시 실제 요청 payload의 X 선택, 1회 전송, 버튼 잠금, 도착 후 대기, 서버 오답 수신 후 X 위치의 슬픈 자세를 확인한다. jsdom은 픽셀 백엔드가 없으므로 픽셀 모양 자체는 아래 브라우저 검수로 확인했다.

## 브라우저 검수 — 통과

개발 서버 전용 `frontend/e2e/fixtures/answer-motion.html`에서 실제 제품 컴포넌트와 캐릭터 아트를 사용했다. 기본·1번·5번 장비 × 9명 × 6개 포즈 = 162개 캔버스의 렌더링 완료를 확인했다. 외형·머리·양팔·다리와 장비의 시각 검수를 수행했다.

- O 클릭: 왼쪽을 바라보며 걷기 → O 위치 → 양팔을 올린 정답 자세.
- X 키보드 Enter: 오른쪽 이동 → 보라와 5번 장비를 착용한 오답 자세.
- X 응답 대기: `waiting`과 X 위치 유지 → 서버 정답 버튼 → 정답 반응.
- 360px 뷰포트: 캐릭터가 장면 안에 들어가고 선택 지점과 캐릭터 중심의 차이는 0px. 문서 가로 넘침 없음.
- HMR 과정의 검수 페이지 중복 root 경고를 방지하도록 해제 처리를 추가하고 새로고침 후 확인했다.

실제 운영 계정이나 운영 DB는 사용하지 않았다. 백엔드 변경이 없어 전체 HTTP E2E를 새로 실행하지 않았으며, 서버 연동은 기존 MSW 통합 경계에서 검증했다. 운영체제의 동작 줄이기 설정은 변경하지 않았고 해당 동작은 포즈 단위 테스트와 CSS 검토로 확인했다.

## 리뷰와 재현

변경·신규 파일 전체를 자체 검토했다. 머지 전 독립 리뷰 에이전트가 `origin/main...HEAD` 및 손 관절 호환 수정을 검토했고, 구체적인 정확성 차단 문제 없음·머지 가능으로 판정했다. 포즈·장면·학습 통합의 집중 테스트 43개도 통과했다. 리뷰어의 실수로 실행된 Node 22 전체 검사에서는 기존 옷장/문항 대화상자 테스트 두 개가 실패했으나, 필수 환경인 Node 24의 전체 299개는 통과했다. 해당 Node 22 실행을 릴리스 판정 근거로 사용하지 않는다. 답변 및 다음 문제 요청 경로를 유지하고, 문항별 키로 장면 수명을 분리하며, 프레임/타이머/AbortController 정리를 확인했다.

이 브랜치에서 `pnpm --dir frontend dev --port 8103 --strictPort` 실행 후 `/e2e/fixtures/answer-motion.html`을 열면 캐릭터·장비 선택, O 정답, X 오답, 응답 대기와 전체 포즈를 확인할 수 있다. 검수 페이지는 배포 번들에 포함되지 않는다.


## 녹화 및 릴리스 후보 검증

사용자의 녹화·PR 머지·기존 링크 배포 요청에 따라 최신 main 위에 이 기능의 세 커밋만 재배치했다. 다른 UI 변경은 포함하지 않았다. PR 준비 중 main에 보상 시네마틱 PR #8이 머지되어 이를 통합했다. 재배치 중 학습 페이지의 import 충돌을 main의 기존 XP 표시를 유지하며 해결하고, 손 관절 좌표를 이 기능에서 독립 제공하도록 했다.

[실제 컴포넌트 동작 녹화](recordings/2026-10-19-answer-character-motion.mp4)는 13.72초, H.264 736×536, 850,262바이트다. 검수 페이지의 정상 버튼 입력으로 O 정답 → 새 문항 → 보라의 X 오답 → 새 문항 → X 응답 대기 → 서버 정답 반응을 녹화했다. 계정이나 운영 데이터는 사용하지 않았다. 브라우저 pageerror 0, 162개 포즈 렌더 완료, 캐릭터와 O 목적지 중심 차이 1px 이내를 확인했다.

운영 배포는 기존 `hanbit-prod`의 `web`만 빌드·교체한다. 배포 전 웹 이미지 ID를 별도 태그로 보관하고, 롤백 시 같은 기존 이미지로 웹만 되돌린다. DB·백엔드·터널의 컨테이너 ID를 전후 비교한다. 배포 완료 판정은 HTTPS HTML/JS/CSS와 로컬 빌드의 일치, 익명 CSRF/인증 경계, 보호된 학생 경로의 로그인 전환으로 확인한다. 학습 상호작용은 검수 화면과 통합 테스트 증거이며 실제 학생 데이터를 변경하지 않는다.


### 최신 보상 연출과 순서 통합

`22ec29c`를 통합하면서 전체 화면 XP가 걷기/감정 반응을 가리는 의미 충돌을 발견했다. `ExperienceReward`의 선택적 지연 상태는 지급액을 즉시 표시하되, 장면이 도착 후 정답 1,200ms / 오답 450ms 반응을 마치면 해당 답변 ID의 보상만 관찰·재생한다. 기존 보상의 기본 동작은 그대로이며, 다음 문제·계정 변경·이탈은 장면 타이머를 취소한다. 독립 리뷰는 이 후속 변경도 다시 검토하여 정확성 차단 문제 없음으로 판정했다.

최종 Node 24 검사: 39개 파일 / 304개 테스트, 빌드, 린트 통과. 회귀 테스트는 지연 중 XP 금액 표시·대화상자 없음, 지연 해제 뒤 1회 재생, 이동 및 반응 종료 전 해제되지 않음을 검증했다.

실제 `/student/learning/sessions/{id}` 제품 라우트를 별도의 Chromium 문맥에서 열고 합성 API 응답으로 점검했다. O 클릭 → 걷기 → 기쁨 → XP, 다음 문항 초기화, X 클릭 → 걷기 → 슬픔 → XP 순서 통과. 전송 답변은 2회, pageerror 0, 360px 문서/스크롤 폭은 모두 360px. 운영 계정이나 실제 학습 기록은 사용하지 않았다.
