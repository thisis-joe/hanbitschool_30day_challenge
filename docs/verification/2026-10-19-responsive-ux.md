# 2026-10-19 사용자 흐름·반응형 UI 개선

요청: 가로로 놓을 수 있는 버튼의 불필요한 세로 배치를 찾고, 학생·교사·관리자가 실제로 사용하는 흐름을 개선한다.

브랜치: `feat/responsive-ux-flow`. 시작 기준은 `d507be5`. 작업 중 기존 장비 아트 변경이 `86f3a7b`로 별도 커밋되었으며, 해당 변경과 기존 미추적 파일은 보존했다.

## 검증

- Node 24, pnpm 11.25.0: 단위 테스트 **37개 파일·293개 통과**.
- `pnpm --dir frontend build`, `pnpm --dir frontend lint`: 통과.
- `ux-flow.spec.ts`: **29개 통과**. 학생 홈·문제·옷장·캐릭터·지도·계정·비밀번호, 교사 학급·통계·학생 상세, 관리자 계정, 학생 로그인·가입·교직원 로그인을 320·390·768·1280px에서 검증했다.
- `game-celebrations.spec.ts`: **3개 통과**. XP·선물 연출 중 행동, 착용 저장, 재방문, 모션 감소 유지.
- 실제 서버 통합 검증: **18개 통과**(아래 분류). `.superpowers/ux-audit/integration`에 현재 소스의 격리 사본을 만들고, 새 테스트 자격 증명과 `hanbit-ux-e2e` 전용 DB·컨테이너·루프백 8097 포트를 사용했다. 기존 환경 파일은 읽거나 재사용하지 않았다.
- 통합 검증 분류: 학습 5개(결과 저장·재학습·이어풀기·서버 시간초과·복습/별표), 게임 3개(재로그인 후 외형 유지·최초 선물·미보유 미리보기), 인증 9개(반응형·키보드 오류), 교사 통계 1개(명단·검색·학생 상세·목록 복귀).
- 초기 통합 실행의 3개 실패는 접힌 회차를 펼치지 않은 테스트 동선이었다. 로딩을 기다려 목록을 펼치도록 도우미를 수정했다. 복습 대상이 없는 상태는 버튼 부재를 확인하도록 기대값을 변경했다. 수정 후 해당 시나리오를 모두 재검증했다. 서버 저장·XP·소유권·타이머 검증은 유지했다.
- 통합 검증 사본과 최종 제품 소스(`frontend/src`, `backend/src`, `infra`)를 파일 내용으로 비교하여 차이 0건을 확인했다. 테스트 종료 후 이 작업의 `hanbit-ux-e2e` 컨테이너만 중지했으며 DB 볼륨은 보존했다.
- 자기 검토: 현재 커밋·추가 테스트·모바일/데스크톱 렌더링을 함께 확인. 독립 리뷰는 수행하지 않았다.

API를 대체한 화면 테스트는 레이아웃·행동을 검증하며 서버 저장의 증거와 구분한다. 서버 저장과 타이머는 위 실제 통합 결과로 별도 확인했다. 운영 사이트 배포는 이 작업에 포함하지 않았다.

## 재현 명령

기본 프런트엔드 검증:

```sh
npx --yes --package=node@24 --package=pnpm@11.25.0 -c 'pnpm --dir frontend test && pnpm --dir frontend build && pnpm --dir frontend lint'
# 별도 터미널에서 동일 Node 버전으로 pnpm --dir frontend dev --port 5173 --strictPort
HANBIT_E2E_BASE_URL=http://127.0.0.1:5173 pnpm --dir frontend exec playwright test e2e/ux-flow.spec.ts e2e/game-celebrations.spec.ts
```

실제 통합 검증은 현재 소스와 동일한 격리 사본에서 수행했다. 사본의 `.env.e2e.local`은 새 테스트 전용 값이며 권한 600이다. 컨테이너의 프로젝트·작업 디렉터리·설정 파일·루프백 포트 소유를 확인했다. 다음 명령은 해당 사본을 작업 디렉터리로 사용한다.

```sh
HANBIT_E2E_BASE_URL=http://127.0.0.1:8097 HANBIT_E2E_COMPOSE_PROJECT=hanbit-ux-e2e \
  pnpm --dir frontend exec playwright test \
  e2e/learning-flow.spec.ts e2e/responsive-auth.spec.ts e2e/ux-live.spec.ts e2e/game-flow.spec.ts \
  --grep 'studentCan|failedDay|questionAnd|expiredQuestion|privateQueue|characterWardrobe|firstPassGift|lockedPreview|no overflow|keyboard reaches|teacher can'
```

운영 배포·전체 백엔드 단위 테스트 재실행은 하지 않았다. 변경 범위는 프런트엔드이며 실제 백엔드 연결 테스트로 변경된 사용자 흐름을 확인했다.

## 2026-10-20 main 통합과 릴리스 후보 검증

운영 배포 및 푸시·PR·병합 요청에 따라 `origin/main`의 `9c7caab`을 현재 기능 브랜치에 통합했다. main의 답변 캐릭터 동작, 전체 화면 보상 연출, 반응 완료 후 XP 연출 순서를 유지했다. 기존 보상 구현이 양쪽 이력에 중복되어 생긴 6개 파일의 충돌은 최신 연출을 유지하고 학습 버튼·타이머의 UX 변경을 함께 적용하여 해결했다. 별도의 `dev`/`develop` 브랜치는 없으며 저장소 기본 PR 대상은 `main`이다.

- Node 24 / pnpm 11.25.0: 단위 테스트 **39개 파일 / 307개 통과**, build·lint 통과.
- 통합 브라우저 회귀: `ux-flow.spec.ts` 29개 + 최신 `game-celebrations.spec.ts` 5개 = **34개 통과**. 320/390/768/1280px 레이아웃, 선택 복습, 옷장 왕복 포커스, 교사 검색, 키보드, 보상 시네마틱 종료·건너뛰기·동작 줄이기를 확인했다.
- backend·infra·의존성은 최신 main과 동일하다. 기존 실제 격리 서버 18개 통과는 이전 UX 소스에 대한 증거이며, 이번 34개는 통합된 프런트엔드와 합성 API의 실제 브라우저 증거다.
- 이 항목은 병합 전 검증이며 운영 배포·인증된 운영 동작의 성공을 의미하지 않는다.
